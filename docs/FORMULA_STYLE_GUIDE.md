# Markdown 公式书写规范

本规范适用于仓库内所有含数学公式的 Markdown 文档，目标是在 GitHub 页面中稳定渲染，并避免编辑器或编码转换破坏公式与中文正文。

## 推荐写法

- 行内公式使用成对的单美元符号，例如 `$Z=fB/d$`。公式与中文标点可以相邻，但 `$` 必须成对且不能放进反引号代码范围。
- 独立公式使用单独成行的双美元符号：

  ```markdown
  $$
  H(x,y,t)=Z(x,y,t)-Z_0(x,y)
  $$
  ```

- 矩阵和多行公式放在 `$$` 块中。矩阵行使用 `\\` 分隔；需要对齐或分段时使用完整配对的 `aligned`、`bmatrix` 或 `cases` 环境：

  ```markdown
  $$
  \mathbf K=\begin{bmatrix}
  f_x & 0 & c_x \\
  0 & f_y & c_y \\
  0 & 0 & 1
  \end{bmatrix}
  $$
  ```

- Markdown 表格中的短公式使用 `$...$`，例如 `| 深度 | $Z=fB/d$ |`。复杂矩阵或多行公式不要放在表格单元格中，应移到表格前后作为独立公式，并在单元格中引用公式名称。

## 禁止或避免的写法

- 不使用 `\[` 和 `\]` 作为块公式定界符；统一使用 `$$`。
- 不使用单独一行的单个 `$` 包围块公式。
- 不把需要渲染的公式放进反引号或围栏代码块；代码块只用于展示 Markdown 写法示例。
- 不留下未配对的 `$`、`$$`、`\begin{...}` 或 `\end{...}`，也不要混用不同的块公式定界符。
- 不为“修复显示”而重复增加反斜杠。LaTeX 命令保留一个反斜杠，矩阵和多行环境的换行保留两个反斜杠。

## 提交前检查

任何新增或修改含公式的文档都必须遵守本规范。提交前应确认文件保持 UTF-8 编码，在 GitHub Markdown 预览中检查行内公式、块公式、矩阵、多行环境和表格公式，并做仓库级文本扫描，排除未配对定界符、`\[`/`\]`、错误转义及公式被代码语法截断等问题。
